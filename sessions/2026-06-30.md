## 4. Bug anime en móvil — INTENTO DE FIX, NO RESUELTO ⚠️

**Síntoma:** al reproducir un episodio de anime en móvil (iPhone, Chrome/WebKit),
tras "Tardando más de lo normal" termina en error de JW Player: *"This video file
cannot be played. (Error Code: 102630)"*. Confirmado por el usuario que **solo
falla en móvil** — desktop y TV funcionan con el mismo navegador Chrome (misma
cuenta, mismo título), la diferencia es el motor de renderizado (WebKit obligatorio
en iOS vs. Blink en desktop/TV).

**Hipótesis (no confirmada end-to-end):** los servidores de embed de anime por
defecto usan HLS, que depende de MSE (Media Source Extensions); Safari/WebKit en
iOS restringe/bloquea MSE dentro de iframes de terceros → error 102630. Blink
(desktop/TV) sí lo soporta.

**Fix intentado (`PlayerView.vue`, commit `361a3e5`):**
```js
function pickDefaultAnimeServerIdx(filtered: AnimeServerEntry[]): number {
  if (deviceStore.isMobile) {
    const mp4Idx = filtered.findIndex((s) => /mp4/i.test(s.label));
    if (mp4Idx >= 0) return mp4Idx;
    const nonHlsIdx = filtered.findIndex((s) => !/hls/i.test(s.label));
    return nonHlsIdx >= 0 ? nonHlsIdx : 0;
  }
  const hlsIdx = filtered.findIndex((s) => /hls/i.test(s.label));
  return hlsIdx >= 0 ? hlsIdx : filtered.length > 1 ? 1 : 0;
}
```
En móvil, prefiere MP4Upload (progresivo, no depende de MSE) o cualquier servidor
no-HLS como default, en vez de HLS. Desktop/TV sin cambios (siguen con HLS
default). Usado tanto en la carga inicial (`fetchAnimeServersForEpisode`) como al
alternar SUB/DUB (`switchAnime1Lang`).

**Resultado: el usuario confirmó que el fix NO solucionó el problema** ("no se
reproduce"). Se intentó investigar con WebSearch pero la herramienta devolvió
límite de sesión alcanzado (sin resultados útiles) — la investigación externa
quedó inconclusa, no se descartó por evidencia sino por límite de herramienta.
