# ADR-001 — Arquitectura por capas (lógica pura vs efectos) + DI de clientes

- **Estado:** Aceptada
- **Fecha:** migración Vue 3 (vigente 2026-06-09)

## Contexto
El original es un monolito vanilla JS (~9.600 líneas) con lógica de negocio mezclada
con manipulación de DOM, red y timers. Difícil de testear y mantener.

## Decisión
Separar en capas:
- `services/` → **lógica PURA** (sin DOM/efectos) + "clients" de red. **100% testeada** con Vitest.
- `composables/` → **orquestación** con efectos (DOM, `<video>`, MediaSource, red, timers).
- `stores/` → estado reactivo (Pinia) + persistencia.
- `components/`/`views/` → UI declarativa.

La decisión de "qué hacer" se extrae a funciones puras; el composable solo aplica el
resultado sobre el mundo real. Los clientes de red se arman UNA vez en `bootstrap.ts`
y se inyectan vía `app.provide(APP_SERVICES_KEY)` / `useAppServices()`.

## Consecuencias
- (+) Scoring/matching/parseo testeables sin browser (251 tests).
- (+) Menos estado global; cancelación async vía "generaciones" (`playerStore.generation`).
- (−) Más archivos/indirección que el monolito.
- Cada bloque migrado referencia su origen (`// preserva ... índex.html línea ~XXXX`).
