# ADR-007 — Barra del navegador webOS en TV: Fullscreen API al volver + nav `position: sticky`

- **Estado:** ✅ Implementada (2026-06-13) — funcional, "falta afinar" (ver Consecuencias)
- **Decisores:** usuario (Angelo) + diseño técnico
- **Relacionada:** `architecture/player.md` §7, `architecture/components.md` (NavTV),
  `coding-standards.md` (Lecciones TV/webOS)

## Contexto

En el navegador de la smart-TV LG (webOS), tras reproducir una película y volver con
"Volver", **la barra del navegador (URL/controles) reaparece y tapa el nav fijo de la app**.
En la primera entrada no pasa: el chrome del navegador está oculto y el nav se ve perfecto.
El ciclo de reproducción hace reaparecer la barra de webOS.

## Problema

Ocultar la barra del navegador webOS de forma fiable, manteniendo el nav (Inicio/Películas/…)
visible y pegado arriba al hacer scroll, **solo** después de reproducir.

## Alternativas evaluadas

1. **`forceExitNativeFullscreen` incondicional al cerrar** → EMPEORÓ: salir de fullscreen
   muestra la barra. Descartada (regresión).
2. **No tocar el Fullscreen API en TV** (solo overlay CSS) → la barra reaparece igual tras el
   ciclo de reproducción; insuficiente.
3. **Micro-scroll (`window.scrollTo(0,1)`) al volver**, replicando el gesto que en Home oculta
   la barra → no fiable en webOS (la barra no se oculta con scroll programático).
4. **`requestFullscreen` al volver + nav `position: fixed`** → oculta la barra PERO rompe el
   `position:fixed`: en webkit, un `fixed` dentro de un elemento en `:fullscreen` deja de
   pegarse al scrollear → el nav "desaparecía" al bajar.
5. **`requestFullscreen` al volver + nav `position: sticky`** → ✅ elegida.

## Decisión

- **`PlayerView.closePlayer()`**: en TV pide `document.documentElement.requestFullscreen()`
  (es un gesto del usuario: el clic en "Volver"). Es el único modo fiable de ocultar el chrome
  del navegador webOS. **No** se hace `exitFullscreen` en TV (`useFullscreen` lo gatea por
  `isTvMode`), porque salir volvería a mostrar la barra.
- **`NavTV.vue`**: `position: fixed` → **`position: sticky`**. `sticky` se basa en el
  scroll-container (no en el viewport), así que **sobrevive** al `:fullscreen` de webkit donde
  `fixed` se rompe. Como el nav es el primer elemento del flujo, queda pegado en `top:0` igual
  que `fixed`.
- **`App.vue`**: se quita `padding-top:76px` de `.app-main` en TV (el nav sticky ya ocupa esos
  76px en el flujo). Visualmente idéntico.
- **`useFullscreen`**: durante la reproducción NO toca el Fullscreen API nativo en TV (el overlay
  CSS `.player-page` ya cubre la pantalla).

## Consecuencias

**Positivas:**
- El nav queda visible y pegado arriba al scrollear, también tras reproducir.
- La barra del navegador webOS queda oculta de forma estable (no se hace exit en TV).

**Negativas / pendientes:**
- Tras la primera reproducción la app queda en fullscreen del navegador (efecto deseado: chrome
  oculto). 
- El usuario indicó que "falta afinarlo algo" — comportamiento aceptable pero no perfecto.
- **Solución definitiva:** empaquetar la app como **PWA / webOS `.ipk`** (sin chrome de
  navegador). Elimina el problema de raíz. Ya está en el backlog (project-memory §4).
