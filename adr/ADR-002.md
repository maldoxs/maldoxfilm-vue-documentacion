# ADR-002 — RD_TOKEN server-side vía Netlify Function

- **Estado:** Aceptada (Fase 1; Fase 2 proxy completo pendiente)
- **Fecha:** 2026-06-09

## Contexto
El original hardcodeaba el RD_TOKEN en el cliente → quedó **comprometido/público**.
El token da acceso total a la cuenta Real-Debrid.

## Decisión
El token NUNCA va al bundle del cliente, ni a `.env` con `VITE_*`, ni a git.
Se sirve vía Netlify Function `rd-token` que lo lee de `process.env.RD_TOKEN`:
- Local: `.env` gitignored, servido por `netlify dev`.
- Prod: env var del panel de Netlify.
El cliente lo obtiene en runtime con `fetchRdToken()` (`bootstrap.ts`). Si la function
falla → token `''` (modo degradado seguro).

## Consecuencias
- (+) Token fuera del bundle y de git.
- (−) **Requiere `netlify dev`** en local (no `npm run dev`) para que las functions corran.
- (−) **Fase 1**: el token aún viaja por la red al cliente (visible en Network). La
  **Fase 2** (proxy completo, el navegador nunca recibe el token) queda pendiente.
- Si el token expira → `/downloads` falla → `rdId null` → caída a iframe. Rotar token
  = editar `.env`/env var + **reiniciar** `netlify dev`.
