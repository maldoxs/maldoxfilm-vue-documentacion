# ADR-005 — Fuente de subtítulos: OpenSubtitles (NO usar subs embebidos de RD)

- **Estado:** Aceptada (2026-06-10)
- **Decisores:** usuario (Angelo) + investigación técnica

## Contexto

Todos los subtítulos pasan hoy por **OpenSubtitles** (`useSubtitles.ts` + function
`subhash`). Surge la idea de usar también los subtítulos que trae **Real-Debrid**
(embebidos en el archivo del release) filtrados a español, y caer a OpenSubtitles solo
si no hay — buscando mejor sincronía y ahorrar la cuota diaria de OpenSubtitles.

## Investigación realizada

Log de diagnóstico temporal en `usePlayer.loadDashViaShaka`:
`console.warn('[SUB][RD-DIAG] Shaka text tracks:', player.getTextTracks())`.

Resultado al reproducir un Dual-Lat (Jack Ryan, multi-audio, vía DASH/Shaka):
```
[SUB][RD-DIAG] Shaka text tracks: []
```
**El transcode DASH de RD NO expone pistas de subtítulos** (Shaka no ve ninguna). RD
transcodifica video+audio para streaming pero deja los subtítulos fuera del manifest.

## Decisión

**Mantener OpenSubtitles como única fuente de subtítulos.** NO implementar la extracción
de subs de RD.

Razones:
- **Vía A (subs nativos en el DASH)** queda descartada empíricamente (`[]`).
- **Vía B (`/streaming/mediaInfos/{id}`)**: lista subtítulos embebidos pero RD no ofrece
  un endpoint estándar para descargar ese `.srt` muxeado de forma limpia → incierto y
  complejo, con beneficio dudoso.
- **Confirmación por documentación oficial (revisada 2026-06-10):** la API de RD NO tiene
  ningún endpoint de subtítulos. Recorridos todos los namespaces (user, unrestrict,
  traffic, streaming, downloads, torrents, hosts, settings, support), el único que toca
  el tema es `mediaInfos`, que solo LISTA las pistas embebidas (metadata: idioma/tipo)
  SIN dar enlace de descarga. → RD no permite recuperar el `.srt` para reproducirlo.
- OpenSubtitles **ya funciona** (Spanish casi siempre disponible), y el **offset ±s** del
  panel corrige la sincronía cuando hace falta.

## Consecuencias

- (+) Sin trabajo extra ni complejidad; flujo de subtítulos actual intacto.
- (−) Se sigue dependiendo de la cuota diaria de OpenSubtitles y de su sincronía
  (mitigada por el offset).
- El log de diagnóstico se eliminó tras obtener el resultado.

## Reapertura

Reabrir solo si: (a) RD cambia su transcode para incluir text tracks (probar de nuevo el
log de `getTextTracks()`), o (b) aparece una forma fiable de extraer el `.srt` embebido
vía `mediaInfos`.
